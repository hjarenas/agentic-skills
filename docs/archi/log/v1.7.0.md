# v1.7.0

## 2026-08-23 — worker lanes, worktree bootstrap and release fan-out

Worktree isolation gained a second, finer scale: a **lane** — one worker's exclusive writable path
set for one dispatch — because two workers in one worktree share a working tree and a git index and
so get nothing from the worktree itself. The git index sits outside every lane (it belongs to
`workspace-worker`, dispatched alone), and where no disjoint lane can be drawn the workers are
serialized instead. Destructive git (`git stash`, `git checkout -- <path>`, `git restore`,
`git reset --hard`, `git clean`) is now denied to every role, since a TRIP working tree routinely
holds the only copy of every batch until release; the positive replacement is to rewrite forward.
Worktree creation gained a bootstrap step — a worktree carries only tracked files, so absent `.env`
and `node_modules` made gates fail like real regressions — recorded per project in `docs/TRIP.md`
alongside what is shared per machine rather than per worktree, plus a `git worktree` permission
allowlist that had been the hidden serializer of parallel phases. `TRIP-3-release`'s artifact steps
now fan out across three lane-scoped `release-worker` dispatches with one verifier over the combined
diff, and its push step checks for a stale base with `git fetch` + `git merge-tree` rather than
rebasing a branch that already carries an open pull request.
