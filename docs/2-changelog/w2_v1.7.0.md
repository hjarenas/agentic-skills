## Changes

- **`trip` plugin (1.6.0 → 1.7.0)**: closed five framework gaps that TRIP users had been working
  around by hand in every dispatch prompt. The evidence is unusual for this repo: 37 Claude Code
  transcripts from a downstream project running TRIP were mined for **tool-result error traces**
  rather than for user corrections — what actually failed at execution time, not what someone
  complained about. All five gaps are additive prose; no scripts and no behavioral code.
  - **Lanes** (`references/agent-routing.md`, new section): a **lane** is one worker's exclusive
    writable path set for one dispatch. Worktrees isolate a *phase*; lanes isolate a *worker
    inside* a worktree — two workers sharing one worktree share a working tree and a git index, so
    the worktree grants them nothing. The transcripts contained **86 hand-written "another agent is
    concurrently editing X — do not touch" warnings**, which is the same contract written 86 times
    by hand. Lanes prevent three silent failures: a tree-wide formatter rewriting a sibling's
    mid-edit files, `git add -A` sweeping up a sibling's half-finished work, and two workers
    overwriting one file. The **git index sits outside every lane** — it belongs to
    `workspace-worker`, which is dispatched alone. The rule closes on the negative case: **no lane
    ⇒ no concurrency**, serialize instead.
  - **Destructive git banned for every role** (`references/agent-routing.md`, new section):
    `git stash`, `git checkout -- <path>`, `git restore`, `git reset --hard`, `git clean`. TRIP
    projects may defer committing until release, so the working tree routinely holds the **only**
    copy of every batch so far — these commands destroyed uncommitted work twice in the downstream
    project. The positive target is **rewrite forward**: undo an edit by writing the intended
    content again, never by reaching for a command that discards.
  - **Worktree bootstrap** (`TRIP-init` profile subsection "Bootstrapping a fresh worktree", wired
    into `skills/TRIP-2-implement/SKILL.md` and `phase-scheduling.md`, migrated by `TRIP-upgrade`):
    a worktree carries only **tracked** files, so gitignored config (`.env`) and installed
    dependencies (`node_modules`) are simply absent — and the gate that then fails looks exactly
    like a real regression. The profile now records both the bootstrap steps and what is shared
    per-machine rather than per-worktree (Docker, fixed ports), which is the other half of the same
    question.
  - **Git permission allowlist** (`TRIP-init` new Phase 5b, migrated by `TRIP-upgrade`):
    `git worktree` was never pre-approved, so autonomous runs stalled on permission prompts and
    parallel phases quietly serialized behind them — the parallelism was there, the approvals were
    the bottleneck. The allowlist deliberately **excludes** destructive git and `git push --force`
    so those keep prompting.
  - **Release fan-out and stale-base check** (`skills/TRIP-3-release/SKILL.md`): Steps 1-8 were one
    serial dispatch even though most of them write disjoint files. Step 1 now runs alone, then
    three **parallel lane-scoped `release-worker` dispatches** — version+README, code-review+changelog,
    and `wiki-ingest` (the long pole) — then Step 4. One verifier still reviews the combined diff,
    so fanning out the writing does not fan out the checking. Step 10 now runs `git fetch` plus
    `git merge-tree` **before** the pull request is opened, and **blocks on `WOULD CONFLICT`**. A
    flow can run for hours while other work merges, and the first anyone usually learns of a stale
    base is a conflicted PR the user has to point out; the check moves that discovery earlier. On a
    conflict it routes back through an `implementer` lane plus a re-run of the testing gate rather
    than a quick rebase, because a conflict resolution rewrites reviewed, gate-verified content and
    so earns review and a gate of its own.
  - **Six agent definitions** (`implementer`, `fixer`, `planner`, `test-worker`, `release-worker`,
    `workspace-worker`) each gained a short pointer using the `lane` / `rewrite forward` /
    `destructive git` tokens back to the contract in `agent-routing.md`, rather than a duplicated
    paragraph that would drift.

  recorded a follow-up claiming three wiki pages carried version stamps disagreeing with their
  plugins, and specifically that `pocock-core-plugin.md` and `trip-wiki-plugin.md` had swapped
  stamps. That was wrong when written. `git log -L` on the version lines shows `pocock-core` has
  been `1.0.0` since it was created and was never `1.1.0`, while `trip-wiki` went `1.0.0` →
  `1.1.0` in commit `5bb6e84`. Current state: `pocock-core` plugin 1.0.0 / page stamp 1.0.0;
  `trip-wiki` 1.1.0 / 1.1.0; `toolbox` 1.0.0 / 1.0.0; `codex-bridge` 1.2.2 / 1.2.2. Every page
  stamp matches its plugin — the note transposed the two plugins' versions and diagnosed a "swap"
  that existed only in its own reading. No future release should act on it. The v1.6.0 changelog is
  left unedited as the historical record of what was believed at the time. Separately,
  `distribution.md` stamping a commit sha rather than a semver is a genuine convention
  inconsistency and remains open; it is untouched here.
