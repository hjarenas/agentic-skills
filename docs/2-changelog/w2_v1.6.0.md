## Changes

- **`trip` plugin (1.5.0 → 1.6.0)**: gave orchestrators a written contract for what to do when a
  dispatched worker's report never arrives. Previously there was no instruction at all, and the
  emergent behavior was an unbounded busy-wait — one observed flow burned roughly five times the
  tokens of its siblings polling for a report whose work had already landed 25 minutes earlier.
  - **Bounded wait** (`references/agent-routing.md`, read by every orchestrator skill and agent):
    waiting is now capped instead of open-ended, so a missing report ends in a decision rather
    than in an ever-deeper chain of monitors.
  - **Evidence over inference**: completion is judged from what is on disk, not from the absence
    of a message. The orchestrator records a dispatch-time baseline and, at the cap, validates the
    delta against it — so "the worker produced its artifacts" is an observation, not a guess. A
    child that shows as finished while the orchestrator is still waiting is treated as a
    contradiction to resolve, not a reason to keep waiting.
  - **Stopped-child resume**: a stopped agent executes no prose, so the recovery rule is addressed
    to whoever dispatched it. The dispatcher resumes the stopped child from its own transcript
    rather than re-dispatching it or re-running the assignment — the work is never lost, it is
    sitting in the phase worktrees.
  - **Orphaned-report relay**: a report that surfaces in the wrong conversation ("the peer session
    is no longer reachable") must now be relayed to the parent that is blocked waiting for exactly
    that verdict. Lost reports proved common rather than exceptional — roughly one delivery in
    three in a single observed live session — so reconstruction and relay are written as normal
    paths, not as emergency procedures.
  - **Merge-slot recovery** (`skills/TRIP-2-implement/phase-scheduling.md`): the serialized merge
    slot was a deadlock by construction — a phase whose worker stopped mid-merge held the slot
    forever and stalled every sibling phase behind it. The slot can now be recovered, but only
    when a read-only audit worker establishes all four of these observations:
    1. **No git operation in progress** — `MERGE_HEAD`, `rebase-merge/`, `rebase-apply/` and
       `CHERRY_PICK_HEAD` are all absent, and the feature worktree is clean, so a paused rebase or
       cherry-pick can no longer be mistaken for a landed merge.
    2. **Feature `HEAD` is a merge commit** (two parents) — not a fast-forward, and not some later
       unrelated commit.
    3. **That specific phase's recorded expected tip is one of `HEAD`'s parents.**
    4. **The remote feature ref, observed with `git ls-remote`, equals that exact `HEAD`.**

    Observations 2-4 are the identity half of the test, and they are what carries the safety
    property: as the skill puts it, "a clean tree and some pushed commit are insufficient; they
    could belong to the wrong phase." Only all four together establish *merge landed; slot
    releasable* for **that** phase, so a sibling phase's merge can never release a slot it does
    not own. Any failed or ambiguous check stops the whole phase-scheduling loop with the slot
    still held — releasing on inferred rather than observed state is the one failure here that can
    corrupt the feature branch.
  - **Completion tags for `discovery` and `planner`**: the two roles that had none now emit them.
    Framed deliberately as **report integrity** — a report is identifiable as complete — rather
    than as a liveness signal, so the tags do not become a second thing to busy-wait on.
  - **Two contradictions resolved** in the existing skill text, so the new wait contract does not
    sit on top of text that disagrees about who is waiting for whom:
    - **Release nesting**: `TRIP-3-release` was read as both a nested child orchestrator and a
      flat continuation of the same one. The nested reading now governs under `TRIP-auto`; the
      flat reading remains correct for a standalone `TRIP-2-implement` run.
    - **User-interaction count**: `TRIP-auto`'s "the user interacts exactly twice" is now scoped
      and made to close arithmetically — surviving prompts are stated as suppressed under
      `TRIP-auto`, and the bounded-wait "stop and surface" is named as a third, exceptional
      interaction rather than silently breaking the count.

The change is purely additive prose plus contradiction repair — no scripts, no behavioral code, and
no change to the phase-skill topology.
