## Changes

The evidence for this release is a month of `trip` runs on a downstream project (`crm`): 32
sessions, 1,728 worker dispatches, about 160 active hours. The review gates earned their cost: plan
review sent back 9 of 27 plans, batch review 29% of batches, and the final code review on one
feature found 1 Critical and 12 Major issues. The losses were between the gates. This release
moves those lessons from the downstream project's memory into the plugin.

- **`trip` plugin (1.7.1 → 1.8.0)**
  - **Waiting by inactivity** (`references/agent-routing.md`). A worker counts as stuck only
    when it shows no new activity for about 15 minutes; elapsed time no longer counts.
    - The 1.6.0 flat cap (3 checks or about 20 minutes) fired on healthy workers, whose p90
      runtime is about 44 minutes.
    - Real stalls were almost always a permission prompt inside a background worker, which the
      user cannot see. They lasted 10 and 16 hours in two runs.
    - Each flow now keeps one watchdog, not one timer per dispatch.
    - No-op polling is banned: one orchestrator spent 2.9 B input tokens on 1,613 `true` calls.
    - An orchestrator may not end a turn with work remaining and nothing in flight. A phase was
      once committed and the next never dispatched, and nobody noticed for 7 hours.
  - **Worker dispatch discipline** (Dispatch contract)
    - Every worktree dispatch carries a literal location check, and workers prefix every
      command with `cd <path> &&` or `git -C`.
    - Commands run in the foreground and stay under about 8 minutes.
    - A denied tool call stops the worker with `BLOCKED: <command>`.
    - Reports are about 25 lines. Full reports were the largest source of orchestrator context
      and the main cause of compactions.
    - Workers may not invoke `TRIP-*` skills. A worker told to load `TRIP-3-release` improvised
      orchestration and hung.
  - **Talking to the user** (new section)
    - Plain language, consequence first, and no internal labels without a gloss.
    - A status reply never ends with "keep going?".
    - A decision the user just made is not asked again.
    - A recommended option never quietly drops the request's goal.
  - **Clean-tree check and staging by path**
    - `git add -A` is gone from `TRIP-2-implement` and `TRIP-3-release`; it had swept
      rewritten fixtures and siblings' work into commits.
    - Batches are staged by explicit path and compared with the phase-wide staged set.
    - The phase commit stages the plan file and the gate-fix paths.
    - A new **integration-fix commit** after the code-review loop captures fixes made after the
      last phase merge. Removing `-A` would otherwise have dropped them from the PR; independent
      review caught this as a Critical.
    - One defined clean-tree check (pre- and post-commit forms, excluding `.codex-bridge/`)
      guards all three commits.
  - **Checkbox ticking** happens once per phase gate instead of a planner dispatch per batch,
    which was about a third of all planner dispatches. The implementer no longer ticks; that
    change is part of the agent patch.
  - **Release ground truth is `origin`** (`TRIP-3-release`)
    - Step 1 fetches once.
    - Every release dispatch measures `origin/<main>...HEAD`.
    - Every figure in an artifact cites the command that produced it.
    - Stale local `main` had produced a false "this PR ships two releases" claim, and the
      verifier had confirmed it.
    - The release commit moves to `workspace-worker`, so a single role owns the git index.
    - The pre-PR "ready to open the PR?" question is gone; it once waited 12 hours after the
      user had said "do it".
  - **Artifact names**
    - `wa_vx.y.z` becomes `w<WEEK>_v<X.Y.Z>` across `trip` and `codex-bridge`. The old
      spelling, with only `a` meant as a variable, shipped a literal `wa_` prefix in three
      released file names.
    - A literal placeholder in the release files is now a verifier finding.
  - **Fewer stalling questions**
    - `TRIP-1-plan` runs plan review without asking; the user always chose "run it".
    - `TRIP-hotfix` stops re-confirming the urgency the user expressed by invoking it, and
      redirects feature requests.
    - `TRIP-auto` forbids self-set checkpoints.
  - **Model routing**
    - New subsection "Model and effort on the subagent harness". A blank row falls back to the
      agent file and then to the orchestrator's own model. After one compaction, that silent
      fallback sent 36 dispatches in a row to the top-tier model.
    - A `subagent:<agent-name>` harness value routes a role to a pinned agent carrying
      `effort:`, the only way to set effort on a native subagent.
    - `TRIP-init` warns against the smallest model tier for git and release roles.
  - **PR template and TRIP-2 wording**
    - The PR template gains a **Scope** section (built / not built, with follow-up issues) and
      drops a generic "verify the smoke test" step that misled once.
    - `TRIP-2-implement` describes its batch loop in harness-neutral terms. Wiki and graph reads
      move from the orchestrator into workers, and "finish small leftovers yourself" is removed.
- **`codex-bridge` plugin (1.2.2 → 1.2.3)**
  - The placeholder rename.
  - `codex-implement` re-dispatches leftovers and, on long batches, ends the turn instead of
    polling.
  - `codex-release` no longer owns the release commit.

## Agent definitions

The release session's automated permission check blocked direct edits to
`plugins/trip/agents/*.md` as self-modification. The changes were therefore reviewed as a patch
and applied unchanged, at the user's explicit request, as their own commit in this release:
- `disallowedTools` gains `EnterWorktree, ExitWorktree, AskUserQuestion, Monitor, ScheduleWakeup,
  CronCreate`; the first two caused the 10- and 16-hour hangs.
- `model:` defaults are added: `sonnet` for worker roles, `inherit` for planner, plan-reviewer
  and code-reviewer.
- A short "Worker basics" block goes into every agent.
- Release-role `origin` rules are added.
- Implementer ticking, release-worker commit ownership, and the `TRIP-*` skill references in
  planner and release-worker are removed.
